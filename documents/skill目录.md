# 技能库目录 (Skills Directory)

本项目工作区共包含以下 36 个预置的 Agent 技能，可通过在对话框中输入对应的唤醒词（Slash Command，即 `/` 加上技能名）触发。

## 🛠 工程与工作流配置 (Engineering & Setup)

| 技能名称 (唤醒词) | 详细功能说明 |
| --- | --- |
| `/setup-matt-pocock-skills` | 配置当前仓库的工程基础技能，设置其 Issue 追踪器、分类标签规则以及领域文档布局。在初次使用其他工程技能前需运行一次。 |
| `/setup-pre-commit` | 在当前仓库中配置 Husky 提交前钩子（Pre-commit Hooks），集成 lint-staged（Prettier）、类型检查和自动化测试，确保提交时的代码质量。 |
| `/git-guardrails-claude-code` | 设置 Claude Code 钩子，在危险的 Git 命令（如 push, reset --hard, clean, branch -D 等）执行前进行拦截。用于防止破坏性的 Git 操作。 |
| `/resolving-merge-conflicts` | 在进行 Git merge 或 rebase 遇到代码合并冲突时，协助你解决这些冲突。 |

## 🏗 架构与领域设计 (Architecture & Domain Design)

| 技能名称 (唤醒词) | 详细功能说明 |
| --- | --- |
| `/domain-modeling` | 构建并打磨项目的领域模型。当你想要确定领域专用术语、确立统一语言、记录架构决策或辅助其他技能维护领域模型时使用。 |
| `/ubiquitous-language` | 从对话上下文中提取领域驱动设计（DDD）风格的统一语言词汇表，标记歧义并提出规范用语。将其保存至 `UBIQUITOUS_LANGUAGE.md` 中。 |
| `/codebase-design` | 为深层模块设计提供共享的规范词汇。当你想设计或优化模块接口、寻找加深代码结构的契机、决定边界接缝或者使代码更加便于测试时使用。 |
| `/improve-codebase-architecture` | 扫描整个代码库寻找架构上的深层优化点，并以直观的 HTML 报告展示出来。你可以从中挑选一项进行重点优化。 |
| `/design-an-interface` | 利用多个并行的子代理（Sub-agents），为一个模块生成多种截然不同的接口设计方案。适用于想要探索不同 API 设计思路、比较模块形态的场景。 |

## 📋 需求与计划拆解 (Planning & Specs)

| 技能名称 (唤醒词) | 详细功能说明 |
| --- | --- |
| `/to-prd` | 将目前的对话综合提炼为一份产品需求文档（PRD），并将其发布到项目的 Issue 追踪器中。纯粹整合已讨论的内容，快速成文。 |
| `/to-issues` | 将计划、设计规范或 PRD 通过垂直切片（Tracer-bullet）的方式，拆解为可以在项目 Issue 追踪器上被独立领取的工单。 |
| `/request-refactor-plan` | 通过详尽的访谈，为你创建一份包含极小提交（Tiny commits）颗粒度的重构计划，并将其转化为 GitHub Issue（重构 RFC）。 |
| `/decision-mapping` | 将一个松散的想法或概念转变为一组按顺序排列的调研工单（Tickets），并驱动它们逐个得到解决。 |

## 🎯 任务执行与审查 (Execution & Review)

| 技能名称 (唤醒词) | 详细功能说明 |
| --- | --- |
| `/tdd` | 测试驱动开发（TDD）。当你想要以“测试先行”的方式构建功能或修复 Bug（红-绿-重构模式），或者需要编写集成测试时使用。 |
| `/implement` | 依据给定的产品需求文档（PRD）或 Issue 列表的具体指示，执行并实现相应的代码功能。 |
| `/prototype` | 快速搭建一个可抛弃的原型（例如一个终端应用以解答状态逻辑，或多个UI变体），帮助具象化设计概念，验证可行性。 |
| `/review` | 从某个固定基准点（如特定 Commit 或 Branch）开始审查代码变化。通过并行代理考察“代码标准”和“功能是否符合 PRD”，展示对比报告。 |
| `/diagnosing-bugs` | 针对棘手 Bug 和性能下降问题的深度诊断循环。当遇到代码报错、运行失败或卡顿时呼叫此技能。 |
| `/triage` | 将 Issue 队列和外部 PR 推入状态机流转：进行分类、复现验证、如果有必要则进行拷问，最后编写适合 Agent 阅读的简报。 |
| `/qa` | 交互式 QA（质量保证）测试环节。通过对话报告 Bug，Agent 在后台检索代码库的上下文及领域语言，并自动帮你填写、提交 Issue。 |
| `/migrate-to-shoehorn` | 代码重构辅助：专门用于将 TypeScript 仓库测试文件中的 `as` 类型断言迁移替换为 `@total-typescript/shoehorn`。 |
| `/generate-operator-logic` | 针对《明日方舟》类游戏引擎专用的业务代码生成技能。根据关于角色伤害计算逻辑的描述，生成具备严密继承和变量命名规范的 Python 脚本。 |

## 📝 写作与内容编辑 (Writing & Editing)

| 技能名称 (唤醒词) | 详细功能说明 |
| --- | --- |
| `/writing-shape` | 将原始的 Markdown 素材或粗略笔记通过对话的方式“塑形”。逐步构建开头、逐段扩展内容，并在列表、表格、引言等排版上进行推敲。 |
| `/writing-fragments` | 通过拷问式的访谈，挖掘用户脑海中零碎的想法片段（如短句、论点），并将其追加到统一的文档中，作为未来成文的原始素材库。 |
| `/writing-beats` | 采用“选择你的冒险”式的节奏点（Beats）写作法。选择一个起始素材，Agent 只写一个节奏点并提供后续发展选项，循序渐进串联为完整文章。 |
| `/edit-article` | 编辑和修饰文章。通过调整段落结构、提升表达清晰度和收紧行文，帮助修订并完善一篇草稿。 |
| `/writing-great-skills` | 关于如何出色地编写和编辑 “Skill” 的参考指南。包含了确保 Skill 稳定且可预测的核心词汇和原则。 |

## 🗣 拷问与交互讨论 (Grilling & Interviews)

| 技能名称 (唤醒词) | 详细功能说明 |
| --- | --- |
| `/grill-me` | 针对一个计划或设计，进行无情且密集的盘问（Interview）。在正式动手实施前做极端情况和边界条件的压力测试。 |
| `/grilling` | 功能同上。当用户明确提及相关触发词，或者想要在动手编码前高强度验证计划时触发。 |
| `/grill-with-docs` | 在执行无情拷问、打磨计划或设计方案的同时，同步为您在后台撰写 ADR（架构决策记录）及对应的词汇表文档。 |
| `/loop-me` | 在当前项目工作区内，针对用户想要建立的工作流（Workflows）规范，反向拷问用户以收集更具体的操作细节。 |

## 📚 知识管理与教学 (Knowledge & Teaching)

| 技能名称 (唤醒词) | 详细功能说明 |
| --- | --- |
| `/obsidian-vault` | 在 Obsidian 笔记库中实现搜索、创建并管理带有维基双链（Wikilinks）和索引的笔记内容。 |
| `/teach` | 在当前工作区环境中，系统性地向你教授一项新技能或开发概念。 |
| `/scaffold-exercises` | 搭建结构化的代码练习脚手架。包含章节目录、问题、参考答案和解析，并确保它们能通过 Lint 检查。常用于编写教程资料。 |
| `/handoff` | 将当前积累的庞大对话上下文进行压缩总结，生成一份简练的“交接文档”，方便其他 Agent 或开发者快速接手目前进度。 |
| `/ask-matt` | 全局技能路由器（Router）。如果你不知道当前的开发场景该使用哪个技能，可以向它求助，它会为你评估并分配最合适的技能流。 |
