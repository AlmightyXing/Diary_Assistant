# 统一词汇表 (Ubiquitous Language)

## 核心领域概念

- **应用使用情况 (App Usage Data)**
  由后台服务通过操作系统 API 收集的数据，记录活跃的前台窗口名称及用户的聚焦时长。该数据经过黑名单或白名单过滤，且**不与**特定的“日程”进行硬性的数据结构绑定（松耦合）。在最终生成日记时，作为独立上下文段落提供给大模型，由大模型进行推理和信息丰富。

- **固定日程模板 (Fixed Schedule Template)**
  用于生成周期性日程的规则配置。它不直接在某天的日历中展示，而是作为后台生成器。修改模板将影响所有尚未被用户主动修改过的未来日程实例。

- **日程实例 (Schedule Instance)**
  特定日期上的具体的单个日程。如果是通过“固定日程模板”生成的，修改某一天的实例（例如修改当天的开会时长）不会影响模板本身。用户界面上应提供从实例跳转到编辑模板的快捷入口。

- **日记生命周期 (Diary Lifecycle)**
  日记数据的流转包含三个明确的阶段：
  1. **草稿阶段 (Draft Data)**：包含日程、应用使用记录和感言。用户可在此阶段核实并删改要提交给大模型的上下文信息。
  2. **生成阶段 (Generated Diary)**：大模型返回的初稿。系统在此阶段提供“重新生成”功能。
  3. **定稿阶段 (Finalized Diary)**：用户进行最终微调并保存后的状态。定稿后的日记将作为正式记录永久保存。

- **自动定稿与数据上传策略 (Auto-finalize & Upload Policy)**
  系统在**初始设置时**会引导用户选择“是否默认自动上传”。
  - **手动上传**：用户点击手动上传时，必定弹出二次确认窗口（提示隐私信息将被发送）。
  - **开启“自动上传”动作**：当用户在设置中首次**开启**该功能时，会弹出二次确认窗口提示相关风险。**此后，触发每天的自动上传将不再弹窗阻断**。
  - **触发自动上传（已开启）**：如果当天的日记仍处于草稿阶段，系统会默默将其发送给大模型获取回复，并直接转为定稿阶段保存。如果处于生成阶段，则挂起提醒用户确认。
  - **触发自动上传（未开启）**：如果用户未开启该功能，系统在一天结束时不会连接大模型，而是直接将当天的**“草稿”当做当日定稿日记**进行存储，并允许用户日后随时二次手动编辑。

- **健康计时策略 (Health Timer Policy)**
  基于系统时间（Wall-clock time）的“死计时”，但受系统睡眠状态干预：
  - 系统休眠时自动挂起计时，唤醒后继续计时。
  - 为用户提供“提前进入下一阶段”和“重新开始计时”的手动控制按钮，强调“提醒”属性而非严格的统计监控属性。

- **隐私策略 (Privacy Policy)**
  - **应用白名单 (App Whitelist)**: 应用数据收集采用严格的白名单模式（Opt-in）。用户在首次使用时被引导设置，仅捕获用户显式允许的应用列表。可在个人中心随时修改。
  - **文本上传确认 (Text Upload Confirmation)**: 文本类数据的隐私风险通过“初次开启功能时授权”与“手动上传时授权”相结合的机制由用户自行把控。
