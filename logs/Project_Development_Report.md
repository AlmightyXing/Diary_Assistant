# 项目开发全流程报告

这份报告根据项目的开发日志汇总而成，展示了整个系统从零到一的架构演进与功能落地过程：

## 第一阶段：项目初始化与基础设施搭建

- **环境搭建**：创建 Python 虚拟环境，并安装 FastAPI, SQLAlchemy, Pydantic, python-dotenv 等后端核心依赖，同时确立了 Electron + React + Vite 作为前端框架。
- **工程化与工作流**：编写了用于未来项目初始化的标准 Workflow 模板；设置问题追踪器，建立领域文档及分类标签规范。
- **代码规范配置**：接入 Husky、lint-staged 和 Prettier 等工具建立代码提交流程和自动格式化机制；生成项目标准的 `.gitignore` 环境隔离规范。

## 第二阶段：需求访谈与系统建模

- **需求对话与边界厘清**：通过多轮建模访谈，明确了“日程模板与实例”的关系、数据的作用域与隐私范围（确认了首次使用引导与严格白名单模式）。
- **流程机制确立**：梳理了 AI 日记生成的“三阶段流转（草稿 -> 生成 -> 定稿）”机制；明确了自动上传与手动保存的业务分支，解决其背后的状态机流转逻辑矛盾。
- **工单生成**：将提炼好的 PRD 需求文档拆解为具体的垂直切片 Issue 工单，为后续多 Agent 并行开发奠定基础，并在期间追加了“桌面悬浮小组件”的新需求。

## 第三阶段：核心业务功能开发

- **基础持久化与日程管理 (Issue-1 & Issue-3)**：在主进程构建基于本地 JSON 文件的轻量级持久化系统；前端开发了日程的 CRUD 面板，并构建了基于固定模板自动调度生成单日临时实例的引擎策略。
- **系统状态感知监控 (Issue-2 & Issue-7)**：后端利用 `pywin32` 定期监听全局窗口，统计活跃时间；结合 SQLite 与白名单实现活跃度监控。衍生开发了基于“久坐”和“用眼”的双重健康空闲计时，搭配系统级强通知 (win10toast) 进行倒计时重置与弹窗提醒。
- **AI 全链路日记生成 (Issue-4)**：封装对大模型（如 DeepSeek/OpenAI）的 HTTP 接口。前端获取日程列表和后台分析追踪数据，并拼装 prompt。后台持久化生成出来的草稿及定稿并返回界面富文本展示。

## 第四阶段：视觉重构与体验优化

- **UI 风格迭代**：经过两轮大的审美尝试。从早期的硬派工业机能风（纯黑白高对比、硬直角），最终转为现代化的简洁风（无边框、纯净背景、粉蓝色系块状点缀）。配合进行了原子化组件拆分（Sidebar, Card, Button）。
- **交互与文案打磨**：大幅度调整字体层级结构，全部组件汉化；增加日历组件的日期高亮、悬浮抽屉交互；强化个人中心页面，新增活动应用自动拉取以供快捷加入白名单。
- **自定义模型参数**：在设置页引入用户自定义 API Key 表单，通过加密传递使得全平台能动态适应不同大模型凭证。

## 第五阶段：高级交互模块扩展

- **常驻桌面悬浮窗 (Issue-8)**：实现无边框、无任务栏底框的透明 Widget。在其中浓缩展示核心日程和健康状态，并增加了点击穿透设置与主界面的双向通信一键唤起逻辑。
- **系统托盘（Tray）与挂起守护**：拦截应用点击关闭的行为，加入“隐藏至后台”与“完全退出”的提示；实现了常驻右下角的状态栏托盘图标。
- **强力回收机制**：为解决系统退出时可能产生的后端孤儿进程问题，通过引入 `taskkill` 等系统强命令确立了生命周期的强制回收护航。

## 第六阶段：交付打包与部署 (Portable 架构改造)

- **代码除错与路径重构**：修复多处 TS 编译报错；针对所有资源的硬编码绝对路径进行重构，全部变更为 `isPackaged` 下的动态相对路由，避免资源引用断层。
- **纯绿色免安装生成**：摒弃传统安装包和单文件打包易残存调试数据的问题，采用 Electron-Builder 的 `dir` 模式。
  - 将 Python 侧后端独立利用 PyInstaller 编译为二进制 `.exe`。
  - 将其内嵌到前端的挂载资源目录。
  - 全部数据数据库和持久化文件就地生成于程序自带的 `data/` 目录。
- **成果产出**：清理掉系统级散落的所有调试残留，最终输出为一个全自包含、拷贝即用、数据同体的 Folder-based Portable App (纯绿色应用目录)。
