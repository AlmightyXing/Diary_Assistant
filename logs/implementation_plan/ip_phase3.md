# Phase 3 开发实施计划 (修订版)

Phase 3 的核心目标是补全剩余的功能页面（日程日历、个人设置中心）、实现自动化机制（自动日记定稿和白名单控制），以及**对应用外观进行“无边框”改造**，彻底完成 PRD 并在视觉上向机能风靠拢。

## Proposed Changes

### 1. 外观改造：无边框机能风窗口 (Frameless Window)
- **Electron 改造**：在 `backend/main.ts` 中设置 `frame: false`，移除 Windows 系统默认的边框和丑陋的白条。
- **自定义标题栏**：在 `App.tsx` 顶部实现一个高度约 30px 的纯黑机能风拖拽条（使用 CSS `-webkit-app-region: drag`），允许用户移动窗口。
- **窗口控制**：在自定义标题栏右侧加入自己绘制的“最小化”和“关闭”按钮（无拖拽属性），并通过 Electron 的 `ipcRenderer` 与 `ipcMain` 进行通信以控制窗口。

### 2. 个人中心 (Settings Tab)
我们将实现一个完整的设置页面，包含：
- **隐私白名单管理**：对接后端的 `/whitelist` 接口，展示当前的白名单应用，支持添加和删除。
- **自动上传配置**：使用 `localStorage` 保存用户设置（是否开启自动上传、上传的目标时间）。
- **隐私确认**：当用户在设置中首次开启“自动上传”时，弹出隐私二次确认提示。

### 3. 日程日历 (Calendar Tab)
我们将实现历史记录的回溯功能：
- **日期获取**：在 `backend/main.py` 中增加一个新的接口 `GET /diaries/dates`，返回所有已有日记的日期列表。
- **月视图渲染**：在前端渲染一个简易月历，高亮显示有日记的日期。
- **点击回溯**：点击高亮日期时，下方（或右侧）展示当天的正式日记内容，允许通过历史视图去查看和再次编辑它们。

### 4. 自动生成与转储机制 (Auto-Finalize Mechanism)
- 在 `App.tsx` 中引入全局计时器（Global Interval），采用**宽容度轮询（如每半小时轮询一次）**。
- **自动定稿**：若检查时发现当前时间**已经超过**目标设定时间，且**今日尚未生成日记**，则静默获取当天的 Schedules 与 App Stats，请求 LLM 生成日记，随后调用 `save-diary` 保存，全过程无弹窗。
- **降级登记**：若一天结束（例如进入新的一天的 00:00，或次日首次打开软件发现前一日数据未处理）时，没有开启自动上传且未生成日记，则将当前的“生数据（未生成的日程和统计概览）”作为当天的正式日记进行保底保存。

### 5. 后端 API 与 Electron 通信扩展
#### [MODIFY] backend/main.py
- 增加 `GET /diaries/dates`：遍历 `diaries` 表格，拉取所有的日期键，提供给前端日历使用。

#### [MODIFY] frontend/electron/main.ts
- 窗口创建改为 `frame: false`。
- 增加 IPC 监听事件：`window-minimize` 和 `window-close`，以响应自定义标题栏的控制指令。

#### [MODIFY] frontend/electron/preload.ts
- 暴露 `window.api.minimize()` 和 `window.api.close()` 给前端 React 调用。

## Verification Plan

### Manual Verification
1. **无边框体验测试**：启动应用，检查系统边框是否消失；尝试拖拽自定义顶部黑条，测试窗口拖动是否流畅；点击右上角自定义关闭按钮，验证应用能否正常退出。
2. **白名单测试**：在“个人中心”页面增删白名单，然后启动相应的应用，检查后端的 `stats` 统计是否受控制。
3. **自动上传宽容度测试**：将目标上传时间设置为当前时间的 5 分钟前（模拟错过时间），验证轮询任务能否在下一次巡检时立即捕获并成功静默生成日记。
4. **日历回溯测试**：切换到“日程日历”标签，点击过去有记录的高亮日期，验证历史日记能否被正确拉取和修改。
